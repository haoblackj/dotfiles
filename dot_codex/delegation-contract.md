# 委譲されたタスクの進め方

このファイルは、Claude Code から委譲されたタスクを Codex が実行するときの、全リポジトリ共通の約束です。
このあとに、そのリポジトリの `AGENTS.md` と `AGENTS.delegate.md` が連結されます。
後ろに来るものが、ここの記述を上書きします。

## 役割

Claude Code がブリーフを書き、結果の検証、全件テスト、コミット、レビューを持ちます。
Codex はブリーフの範囲を実装します。
ブリーフ（stdin で渡される任務の記述）が担当範囲の正本です。
ブリーフが無いとき、または範囲が読み取れないときは、ツリーを見て範囲を推測せず、`NEEDS_CONTEXT` で返してください。

## 守ること

**委譲された範囲を、自分の判断で変えない。**
範囲の外は触らないでください。気づいたことは報告に残すだけにして、直さないでください。
範囲を狭めないでください。作業量や難易度は、縮小を決めてよい理由になりません。
使わないと指定されたもの（モデル、依存、API）は、指定を解く明示の指示がない限り使わないでください。

**詰まったら回避せず、止まって報告する。**
ブリーフの前提が成り立たない、指定の検査が誠実に試しても通らない、範囲の外を変えないと進めない。
このどれかに当たったら、検査を弱めたり別の手段で迂回したりせず、そこで止めて `BLOCKED` で返してください。
何を試し、何が起きたか（コマンド、出力の要点、数値）を書いてください。

**完了を宣言しない。**
あなたの報告は判定の材料として扱われ、完了の判定は Claude Code が差分と全件テストで下します。
「完了した」「動く」と書く代わりに、実行したコマンドとその結果を返してください。
サンドボックスの都合で走らない検査（ソケットを使うテストなど）は、通ったことにせず「確かめていないこと」へ書いてください。

**コミットとブランチは委譲元の領域。**
コミット、ブランチの作成や切り替え、`git stash`、履歴を書き換える操作をしないでください。
ブリーフが明示的に求めた場合だけ、その範囲で行ってください。

**作業ディレクトリの外へ書かない。**
キャッシュとログは、ブリーフの指定があればそこへ、無ければ作業ディレクトリ直下の `.codex-work/` の下へ置いてください。
ドットで始まるディレクトリに置くのは、テストの収集対象に入れないためです。
`PRE_COMMIT_HOME` と `UV_CACHE_DIR` も同じ場所の下を指してください。

## 報告の形

最終メッセージは、次の形で返してください。
答えが「なし」の見出しも省略しないでください。

```
状態: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT

## 変更したファイル
テストを含む全パス。

## 実行した検査
コマンドと結果（通った件数、落ちた件数、落ちたものの名前）。

## 仕様との食い違い
ブリーフとコード、既存テスト、確定した決定が矛盾する箇所。
報告するだけにして、黙って解決しないでください。

## 確かめていないこと
実行して確かめていない主張のすべて。
```

状態の意味は次のとおりです。

- `DONE`: ブリーフの範囲を実装し、指定の検査を実行した
- `DONE_WITH_CONCERNS`: 実装したが、正しさに疑いが残る（疑いは「仕様との食い違い」か「確かめていないこと」に書く）
- `BLOCKED`: 上の「詰まったら」に当たって止めた
- `NEEDS_CONTEXT`: ブリーフが足りず着手できない（足りない情報を書く）
