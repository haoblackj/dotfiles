# 再起動後に DNS 固定が効かない／socat 未導入で ssh-agent が起動失敗

自宅で実機検証して直す。出先では回線条件（v6 無し）とリセット済みで確認できない。

## 見えたこと

WSL を初期化 → フル bootstrap → `wsl --shutdown` で入り直した直後の状態で、2 点。

### 1. DNS が再起動後にトンネルへ戻る（wsl-static-dns が効いていない）

`/etc/resolv.conf` が公開 DNS（1.1.1.1/8.8.8.8/1.0.0.1）ではなく、WSL 自動生成の
`nameserver 10.255.255.254`（dnsTunneling）＋`search esco.co.jp` になっていた。
ヘッダに "This file was automatically generated by WSL" が付く＝WSL が生成している＝
`generateResolvConf=false` が効いていない。かつ `wsl-static-dns.service` も上書きできていない。
ブートストラップ中（run_once_10 の即時書き込み）は公開 DNS で通ったが、再起動後の
定常状態がトンネルに戻る。定常でトンネルの #41595 を踏む余地が残るので、狙いを外している。

戻ったら見る（証拠を取ってから直す）:
- `systemctl status wsl-static-dns.service` — 起動時に走ったか・失敗したか（203/EXEC 等）
- `readlink -f /etc/wsl.conf; cat /etc/wsl.conf` — symlink 先と generateResolvConf=false の有無
- `ls -la /etc/resolv.conf` — symlink か実ファイルか

仮説（未検証）: WSL が symlink の /etc/wsl.conf から [network] generateResolvConf=false を
読めていない（systemd=true は効いているように見えたが、イメージ既定の systemd の可能性もあり
wsl.conf 由来か切り分け未）。あるいは wsl-static-dns.service が multi-user.target で走る前に
WSL が resolv.conf を生成し、サービス側が失敗して上書きできていない。
候補の直し: /etc/wsl.conf を symlink でなく実ファイルで置く（chezmoi の実ファイル配置に変える）。
サービスの Before/After や WantedBy を見直す。generateResolvConf が本当に false になっているかを
まず確定させる。

### 2. socat 未導入で bitwarden-ssh-agent が 203/EXEC 失敗（対応済み）

`socat` を `run_once_10` の基本 apt パッケージへ追加して自動導入にした（手動前提を撤去）。
再起動後に bitwarden-ssh-agent が active になるかは DNS と併せて実機で確認する。

## 見つけた場所

- `wsl.conf`（generateResolvConf=false、systemd=true）
- `wsl-static-dns.sh` / `wsl-static-dns.service` / `run_once_10`（DNS 固定）
- `run_once_99`（bitwarden-ssh-agent の enable/start）、README 前提 4（socat 手動導入）
