# 対話セッションの引き継ぎ

Herdr の同じワークスペースの新しいタブへ、対話セッションの状態と作業場所を引き継ぐ。
`HERDR_ENV` が `1` でない場合、またはクラウドセッションでは、新しいタブを立てられない。
その場合は手順 1 の作業記録のコミットまで行い、リーダーに `/clear` を勧めて止まる。
移るのは、リーダーに「移って」などと声をかけられたときだけで、使用率によらない。
コンテキストの知らせ（40% と 60%）は、応答の最後にリーダーへ一言知らせるためのもので、それだけでは移らない。
移る時機をリーダーが決めるのは、Claude が時機を決めると作業の途中で切ることが多く、そのあとリーダーの言い直しと訂正が増えていたため（haoblackj/dotfiles#87）。

## 手順

1. 作業記録を今に合わせる。
   作業記録はリポジトリの `docs/work/<作業名>.md` で、書き方はスキル `work-record`。無ければ作る。
   引き継ぎのための別のファイルや issue のコメントは書かない（判断と進行状態の正本は作業記録で、issue には持たせない。haoblackj/dotfiles#86）。
   特に次を確かめる。
   - 「次に Claude がすること」が、引き継ぎ先がこれだけ読んで始められる具体さになっている。リーダーの声かけで、受けた依頼に手を付けずに移るときは、その依頼の原文を先頭に書く。
   - 判断の経緯に、この会話で出た判断（採用、棄却、変更）が全部ある。リーダーの言葉は `prts quote` で原文を確かめて引く。
   - 「参照」に、ワークツリーのパスとブランチ、関係する issue と PR、元の session_id（`herdr pane current --current` の `.result.pane.agent_session.value`）、裏で走っている処理とその扱いがある。
   直したら、作業のブランチにコミットして push する。

2. 残りの仕事からモデルとエフォートを選び、理由を一言添える。
   引き継ぎ先のセッションの名前も決める。
   この名前はセッションのタイトルとタブ名になる。
   残りの作業の中身を、20 文字以内でできるだけ短く表す（例「コイカツ読込高速化」「dsh 圧縮の空回り」）。
   「引き継ぎ」の語と、issue 番号だけの名前は使わない（スクリプトが「引き継ぎ」と 20 文字を超える名前を弾く）。
   今のタブにリーダーが手で付けた名前があり、残りの作業にも合うなら、それを使う。

3. 作業記録のパスと、作業フォルダを渡して次を呼ぶ。
   ワークツリーで作業していたら、`--cwd` にそのパスを渡す。

   ```sh
   ~/.claude/scripts/session-handoff.sh --state <作業記録> --cwd <作業フォルダかワークツリー> --title <名前> --model <モデル> --effort <エフォート>
   ```

   スクリプトはセッションを立てるだけで、引き継ぎの文面は打ち込まない。
   打ち込んだ文は受けた側の記録でリーダーの入力と見分けがつかないため、文面は `SendMessage` で送る（受けた側の記録に送り手が残る）。
   失敗したら出力をリーダーに出して止まり、掃除へ進まない。
   成功の JSON（`handed_off: false`、`started: true`、`agent`、`tab`、`pane`、`state`、`title`、`prompt`）から、引き継いだタブとペインを控える。
   `ListAgents` に `title` の名前が出たことを確かめ、`prompt` を `SendMessage` でその名前へ送る（立ててから数秒で出る）。
   名前が出ない、または届けた結果に承認待ちや拒否の知らせがあれば、出力をリーダーに報告して止まる。

4. 引き継ぎで立てたペインを除いて、掃除の候補を出す。

   ```sh
   ~/.claude/scripts/herdr-closable.sh list --exclude-pane <立てたペイン>
   ```

   出力は候補ごとに一行の JSON で、`pane`、`tab`、`session_id`、`title`、`last_reply` を持つ。
   同じワークスペースの idle の Claude が候補になり、自分自身、新しく立てたペイン、ループ中のセッション、最後の応答のあとにユーザーの入力があるもの、transcript を読めないものは除かれる。
   候補ごとに `last_reply` を読み、そのセッションが自分の仕事について「閉じていい」とはっきり書いているものだけを選ぶ。
   「閉じていいか確認させて」のような文は選ばず、迷えば残す。
   セッションに宣言を求めない。
   選んだ候補があれば、一覧の `pane` と `session_id` を `<ペイン>=<session_id>` の形で渡す。

   ```sh
   ~/.claude/scripts/herdr-closable.sh close <ペイン>=<session_id>...
   ```

   閉じる直前に、idle、同じワークスペースの Claude、ループでない、自分でない、タブにペインが一つ、ワークスペースの最後のタブでない、という条件を確かめ直す。
   同じ session_id のままで、transcript が一つだけ見つかり、最後の応答のあとにユーザーの入力が無いことも確かめ直す。
   セッションが替わっていたら `reason: "session_changed"`、新しい入力があれば `reason: "new_input"`、引数の形や transcript の取得に問題があれば `reason: "error"` で残す。
   条件から外れたら閉じず、`result: "kept"` と `reason` を返す。
   結果は各ペインに一行ずつの JSON で、`result: "closed"` には `pane` と `tab`、`result: "kept"` には `pane` と `reason` がある。
   `closed` が返ったタブだけを閉じたと報告する。
   情報の取得や `tab close` に失敗すると `reason: "error"` が返り、その場合は実際には閉じていることもある。
   `error` のタブは「閉じたか確かめられなかった」と報告する。

5. 元のセッションの応答で、引き継いだ先のタブ、閉じたタブ、残した候補とその理由を報告する。
   `tab` が空なら、返された `pane` と `agent` を示し、タブ ID は取得できなかったと書く。
   掃除の結果は新しいセッションへの引き継ぎの文面には入れない。
   最後に「このセッションは閉じていい」と書いて止まる。
