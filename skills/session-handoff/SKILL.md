# 対話セッションの引き継ぎ

Herdr の同じワークスペースの新しいタブへ、対話セッションの状態と作業場所を引き継ぐ。
`HERDR_ENV` が `1` でない場合、またはクラウドセッションでは、新しいタブを立てられない。
その場合は手順 1 の状態の書き出しまで行い、リーダーに `/clear` を勧めて止まる。
40% の知らせなら、いまの依頼をキリの良いところまで進めてから移る。
60% の知らせなら、この依頼に入る前に移る。
リーダーに「移って」などと声をかけられたら、使用率によらず同じ手順で移る。
リーダーがこのまま続けるよう言ったら従う。

## 手順

1. 状態を書く。
   元の session_id は `herdr pane current --current` の `.result.pane.agent_session.value` から取り、状態ファイルの名前と状態の項目の両方にこの値を使う。
   issue があれば、その issue に `## 状態` コメントを書き、一つ前の状態コメントをたたむ。
   issue が無ければ、まず issue を立てることをリーダーに提案して返答を待つ。
   立てるならそこへ書き、却下されたら `~/.cache/claude-handoff/<日付>-<session_id>.md` に書く。
   `/tmp` は使わない。
   状態には、済んだこと、決定、次の一手、作業フォルダ、ワークツリーのパスとブランチ、関係する issue と PR、元の session_id、裏で走っている処理とその扱いを残す。
   60% の知らせやリーダーの声かけで、受けた依頼に手を付けずに移るときは、その依頼の原文を「次の一手」の先頭に書く。
   該当しない項目は、無いことを書く。

2. 残りの仕事からモデルとエフォートを選び、理由を一言添える。

3. 状態コメントの URL か状態ファイルのパスと、作業フォルダを渡して次を呼ぶ。
   ワークツリーで作業していたら、`--cwd` にそのパスを渡す。

   ```sh
   ~/.claude/scripts/session-handoff.sh --state <URLかファイル> --cwd <作業フォルダかワークツリー> --model <モデル> --effort <エフォート>
   ```

   失敗したら出力をリーダーに出して止まり、掃除へ進まない。
   成功の JSON（`handed_off: true`、`agent`、`tab`、`pane`、`state`）から、引き継いだタブとペインを控える。

4. 引き継ぎで立てたペインを除いて、掃除の候補を出す。

   ```sh
   ~/.claude/scripts/herdr-closable.sh list --exclude-pane <立てたペイン>
   ```

   出力は候補ごとに一行の JSON で、`pane`、`tab`、`session_id`、`title`、`last_reply` を持つ。
   同じワークスペースの idle の Claude が候補になり、自分自身、新しく立てたペイン、ループ中のセッション、最後の応答のあとにユーザーの入力があるもの、transcript を読めないものは除かれる。
   候補ごとに `last_reply` を読み、そのセッションが自分の仕事について「閉じていい」とはっきり書いているものだけを選ぶ。
   「閉じていいか確認させて」のような文は選ばず、迷えば残す。
   セッションに宣言を求めない。
   選んだ候補があれば、一覧の `pane` と `session_id` を `<ペイン>=<session_id>` の形で渡す。

   ```sh
   ~/.claude/scripts/herdr-closable.sh close <ペイン>=<session_id>...
   ```

   閉じる直前に、idle、同じワークスペースの Claude、ループでない、自分でない、タブにペインが一つ、ワークスペースの最後のタブでない、という条件を確かめ直す。
   同じ session_id のままで、transcript が一つだけ見つかり、最後の応答のあとにユーザーの入力が無いことも確かめ直す。
   セッションが替わっていたら `reason: "session_changed"`、新しい入力があれば `reason: "new_input"`、引数の形や transcript の取得に問題があれば `reason: "error"` で残す。
   条件から外れたら閉じず、`result: "kept"` と `reason` を返す。
   結果は各ペインに一行ずつの JSON で、`result: "closed"` には `pane` と `tab`、`result: "kept"` には `pane` と `reason` がある。
   `closed` が返ったタブだけを閉じたと報告する。
   情報の取得や `tab close` に失敗すると `reason: "error"` が返り、その場合は実際には閉じていることもある。
   `error` のタブは「閉じたか確かめられなかった」と報告する。

5. 元のセッションの応答で、引き継いだ先のタブ、閉じたタブ、残した候補とその理由を報告する。
   `tab` が空なら、返された `pane` と `agent` を示し、タブ ID は取得できなかったと書く。
   掃除の結果は新しいセッションへの引き継ぎの文面には入れない。
   最後に「このセッションは閉じていい」と書いて止まる。
