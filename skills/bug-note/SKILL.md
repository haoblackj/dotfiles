# Bug Note

## これは何のためか

作業中に見つけたバグを、その場で直さずに書き置く。

その場で修正しようとすると Context Window を圧迫し、Context Pollution につながる。
いま進めている作業の文脈に、無関係なバグの調査結果が混ざるため。

## 手順

`ideas/bugs/` へ1ファイル書いて、本題へ戻る。それだけ。

ファイル名は `YYYY-MM-DD-<短い名前>.md`。
ディレクトリが無ければ作る。作業中のリポジトリの中に置く。

書く内容は3つ。

```markdown
# <一行で症状>

## 見えたこと

<何をしていて、何が起きたか。観測した事実だけ>

## 見つけた場所

<ファイルパスや画面。分かる範囲で>
```

## やらないこと

**調査しない。** 再現確認も、原因の特定も、関連ファイルの読み込みもしない。
見えた時点の情報だけで書く。原因の推定を書かない。

不完全な記録になるが、それでよい。着手するときに調べ直せばいい。
調査こそが本題の文脈を汚すもので、記録の質はそれより優先度が低い。

**修正しない。** 書いたバグには、そのセッションでは着手しない。
別のクリーンなセッションで直す。

**報告を長くしない。** 書いたら本題へ戻る。
セッションの終わりに、書き置いたものを1行ずつ挙げるだけにする。
