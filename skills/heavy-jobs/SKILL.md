# 重い処理と常駐の処理の確かめ方

グローバルの CLAUDE.md の「完遂責任」から移した決まり。
当てはまる場面の項を、作業を始める前に読む。

- モック（偽の CLI を含む）で量や挙動を測る前に、モックが本物と同じ形式で答えることを確かめる。形式が違うと読めない応答として扱われ、数字が実際と大きくずれる。
- 常駐の子プロセスを `uv run`、`nice`、`taskset` のようなラッパー越しに起動するときは、新しいセッションで起動してプロセスグループごと止め、テストのモックも孫を持つ形にする。直接の子だけ止めると孫がパイプを握り、asyncio の `proc.wait()` が返らない（2026-11-06）。
- systemd のサービスから動く機能は、対話シェルの検証で済ませず、`systemd-run --user` の一時のユニットで既定のコマンドを走らせて確かめる。PATH が違い、対話シェルでは見えない失敗がある（2026-11-06）。
- 速さを詰めるときは、目的の操作の時間を決めているクリティカルパスを先に測り、その上の区間だけを縮める。クリティカルパスの外（裏で並走している処理）を縮めても目的の時間は変わらない（2026-10-30）。
- CPU の使用を絞った（`taskset`、`nice`、スレッド数）重い処理は、起動後に `/proc/<pid>/task` の各スレッドの affinity と `/proc/pressure/cpu` を測り、縛りが効いていることを確かめてから並列に増やす。onnxruntime はスレッド数を指定されないとスレッドを各コアへ固定し直し、`taskset` を破る（2026-10-23）。
- 大きなデータを読む処理は、メモリが件数に比例するより速く伸びない形に作り、全件の前に件数を 2〜3 段に変えて小さく走らせ、ピークのメモリ（`/usr/bin/time -v` の Maximum resident set size）の伸び方を測って、全件へ外挿して空きに収まることを確かめてから走らせる。最後の安全策は earlyoom（空きのメモリが 4GiB を切ったら `python` を優先して止める常駐。設定は `/etc/default/earlyoom`）で、自前の監視プロセスやラッパーは足さない。Claude Code 公式の `CLAUDE_CODE_TOOL_MEMORY_LIMIT` は、WSL では Claude Code が `/init.scope` で動いて cgroup を作れず効かない（2026-11-02、npz の配列を行ごとに読み直して WSL を固めた。dotfiles#81）。
