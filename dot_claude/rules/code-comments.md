# コードコメントの方針（2026-09-05追加）

コメントは後続のエージェントが必ず読む永続的な文脈である。誤った自然言語をコードベースへ保存する損害があるので、残す基準を決める。

- 残さない: すぐ隣のコードの言い換え、編集の実況（「〜を追加した」）、一時的な検討の跡、「検証済み」「テスト済み」の宣言。
- 残す: コードとテストから安く復元できない情報。外部の制約、非局所的な不変条件、互換性やセキュリティ上の要件、直感に反する選択の理由。
- 判断基準は「why だけ残す」ではなく「そのタスクに必要で、コードから安く復元できないか」。カテゴリで機械的に切らない。
- コメントは権威ではない。コード・テスト・仕様と食い違ったら、コメントを信じずに検証する。
- コメントを検証の証拠にしない。「ここは検証済み」と書いてあることは検証したことを意味しない。
- トークン節約だけを理由に既存コメントを一括削除しない。「コメントが少ないほどエージェントの品質が上がる」という一般則は研究で支持されていない（根拠はメモリの`reference_code_comment_policy_evidence`）。
