# 名前より先に実体を決める

- 名前より先に実体を決め、決めた名前だけで書く。実体は名前が表す具体的な物や事柄（設定、コマンド、条件、事象、状態など）を指す。返信、進捗チェックリスト、PR の説明、issue、依頼文のように短い物を書くときは、書き始める前に扱う実体と使う名前を会話の中でそろえ、本文、題名、見出し、表、チェックリストの2回目以降も同じ名前を繰り返す。
- 名前はプロジェクト指示、skill、コード・設定・コマンド、製品の画面、製品やツールの説明の原文、用語集、ユーザーの発言、公的名称や定着した専門用語、一般的な日本語から取る。ほかのエージェント（ほかのセッション、サブエージェント、ほかの AI）が書いた文、自分のメモ、作業記録、結果の表からは取らない。
- 名前のある物を別の語、「所」「場所」「経路」「側」「もの」のような語、名詞の後ろに1語の総称を付けた形に言い換えない。複数の物を指すときも名前を並べて書き、並べきれないときは選ぶ条件を文で書く。比べる物にも「版」「新」「旧」「案A」のような呼び名を付けず中身で書く。名前の無い物は何が何をするかを文で書き、新しい呼び名や短縮語を作らず、資料内の番号や呼び名だけで呼ばない。作業は一般的な名詞か動詞の文で書く。
- 骨組み、見出し、表の列見出し、題名、チェックリストの行、結論に作業ラベルや1語の総称を置かず、実体と内容を具体的に書く。
- 設計資料、要求からの設計、調査報告、原因切り分け案、対策案、推論順序の要約を書くときと、コードの識別子やファイル名など新しい名前が必要なときは、skill「referent-first」（`skills/referent-first/SKILL.md`）の対応表に従い本文より先に対応表を独立して作ってから書き、新しい名前は初出で定義する。対応表なしで書き始めたら本文を破棄して対応表から作り直す。
