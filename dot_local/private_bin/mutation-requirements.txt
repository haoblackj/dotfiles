# verify-tests --mutate が使う venv の中身。**版を固定して verify-tests と
# 一緒に配る**（issue #16 の受け入れ条件8）。作り方は道具が1行で出す。
#
#   uv venv ~/.local/share/verify-tests-venv && \
#     uv pip install --python ~/.local/share/verify-tests-venv/bin/python \
#       -r ~/.local/bin/mutation-requirements.txt
#
# **版を固定する理由。**基準ファイル（.mutation-baseline.json）が持つのは
# 生き残った変異体の集合で、その集合は道具の版に依存する。版の違う venv で
# 作り直した基準は前の基準と比べられない。道具が上がったこと自体は
# .mutation-baseline.json の `tools` と今回の版を突き合わせて報告に出るが、
# 「上がったせいか判別力が落ちたせいか」を人が読み分けられるのは、
# 上げたことが意図的なときだけである。
#
# **この venv は既存の機械には自動で入らない。**chezmoi の run_once_ は実行済みの
# 機械では再実行されないため、導入済みの機械には手で入れる（#14/#15 が
# pre-commit について同じ扱いをしている）。venv が無い状態で --mutate を呼ぶと
# 「実行できなかった」に分類され、上の命令が1行出て非0で終わる。
#
# **venv の置き場そのものは道具が HOME からの相対で決める**（MUTATE_VENV =
# ~/.local/share/verify-tests-venv）ので、別の利用者名の機械でも道具は動く。
# **ただし両リポジトリの cosmic-ray 設定の `test-command` には
# /home/yagu001/... という絶対パスが焼き付いている。**cosmic-ray は
# test-command を shlex.split して Popen へ渡すだけで PATH 解決に頼れず
# （頼ると python 不在の環境で全変異体が INCOMPETENT になる）、
# その2行だけが機械に依存する。別の機械へ配るときは
# penguinEx の pyproject.toml と chezmoi の .cosmic-ray.toml の
# test-command を、その機械の HOME で書き換える。
#
# Python 3.14.7 で作った（cosmic-ray は tomllib を使うので 3.11 以上が要る）。
cosmic-ray==8.7.0
universalmutator==1.14.1
pytest==9.1.1
