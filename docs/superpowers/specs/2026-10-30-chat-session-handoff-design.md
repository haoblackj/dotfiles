# 対話セッションの引き継ぎと、終わったセッションの掃除

決定の記録: haoblackj/dotfiles#73

## 目的

ループ以外の対話セッションで、コンテキストが膨らんだときの移り方を、`/clear` の勧めから新しいセッションへの引き継ぎに変える。
`/clear` は打つのがリーダーで、打つまで同じセッションが膨らみ続けるうえ、打てば作業の流れ（ワークツリー、作業フォルダ、決定）が途切れる。
引き継ぎなら、元のセッションがキリの良いところで自分から移り、新しいセッションが同じ作業をそのまま続けられる。

引き継ぎのたびに、同じ Herdr のワークスペースで明らかに終わったセッションのタブを閉じ、タブが溜まるのを防ぐ。

## 前提（いまの仕組み）

- `dot_claude/hooks/executable_chat-context-guard.sh`（UserPromptSubmit）が、対話セッションで一段目（50%、1M の窓で 300K）と二段目（75%、400K）に `/clear` を勧める知らせを入れる（#71）。
- 閾値の計算とループのセッションの判定は `dot_claude/hooks/context-level.sh` にあり、`loop-guard.sh` と共有している。
- ループは二段目で `dot_claude/scripts/executable_loop-handoff.sh` を呼んで、同じワークスペースの新しいタブへ引き継ぐ（#69）。タブの作成、`claude` の起動、引き継ぎの文面はスクリプトが決まった形で行う。

## ゴール

1. 対話セッションのコンテキストが使用率 40% を越えたら、元のセッションは手元の仕事をキリの良いところ（コミットや一区切りの報告が済んだところ）まで進め、そこで決まった手順で新しいセッションへ移る。越えた瞬間に作業を投げ出さない。
2. リーダーが声をかけたら（「移って」など）、40% に届いていなくても同じ手順で移る。
3. 新しいセッションが、元のセッションでやっていた作業をそのまま続けられるものを受け取る。少なくとも、状態（済んだこと、決定、次の一手）、使っていたワークツリー、作業フォルダ（cwd）。
4. 移るときに、同じワークスペースの他のセッションのうち、最後の応答で自分から「閉じていい」とはっきり書いているものを閉じる。判断がつかないものは閉じない。
5. 掃除の結果（閉じたタブ、残した候補とその理由）は、元のセッションの応答としてリーダーに出す。新しいセッションへの引き継ぎの文面には入れない。

## やらないこと

- セッションに「閉じていい」と宣言させる決まりを作らない（リーダーの決定）。決まりにすると、リーダーが続けてほしいのに終わりを宣言されたセッションまで閉じられる。自然に出た「閉じていい」だけを拾う。
- ループの閾値と引き継ぎの挙動は変えない（50% / 75%、300K / 400K のまま）。
- クラウドセッションへは配らない（`chat-context-guard.sh` は今も `install-cloud.sh` の対象外）。

## 失敗とみなすこと（動いても駄目なもの）

- リーダーがまだ続けたいセッション、応答の途中のセッション、ループ中のセッション、新しく立てたセッション、元のセッション自身を閉じる。
- 引き継いだ先が、別の cwd で立ち上がる、ワークツリーを知らない、状態を読まずに始める。
- 40% を越えた直後に、作業を途中で切って移る。

## 決まったこと（リーダーの決定）

- 対話セッションの引き継ぎの閾値は 40%。
- 移るのは元のセッションが自分で、キリの良いところで。声かけでも移れる経路を併せて持つ。
- 閉じる判定は、セッション側が最後の応答で「閉じていい」と明確に書いたかどうか。迷ったら残す。
- 掃除の報告は元のセッションに出す。
- 引き継ぎでは、ワークツリーと作業フォルダを含め、作業を継続できるものを一式渡す。
- 作り方は、今の hooks と bash の延長にする（2026-10-31）。入れるだけで満たす既製品は無かった（近いものは同じ窓で `/clear` するか claude を立て直す方式で、Herdr の別タブへ移らず、ワークツリーも cwd も渡さない）。Claude Code の mod でも作れるが、JS/TS の道具と別のテストの仕組みが増え、ループ側の仕組みと二本立てになるため、いったん見送った。

## 設計（Claude の判断。リーダーの決定ではない）

### 閾値

- 40% は使用率として読み、窓の大きさによらない（1M の窓なら約 400K）。対話用の閾値を `context-level.sh` に足し（例: `CONTEXT_GUARD_CHAT_HANDOFF_PCT`、既定 40）、ループ用の値とは分ける。
- いまの対話の一段目と二段目（`/clear` の勧め）は、この引き継ぎに置き換える。
- 予備の段を一つ残す。40% の知らせのあともキリがつかずに膨らみ続けたとき、たとえば使用率 60% で「次の依頼に入る前に移る」と強めに知らせる。値は実装で決めてよい。

### 知らせ（`chat-context-guard.sh`）

- 40% を越えたら一度だけ知らせる。文面は「いまの依頼をキリの良いところまで進めたら、引き継ぎの手順で移る」。
- 予備の段も一度だけ。下回ったら印を消す（今と同じ）。
- Herdr の外（`HERDR_ENV` が無い）では引き継げないので、今と同じ `/clear` の勧めに落とす。

### 引き継ぎの手順

決まった手順をスキル（公開の自作スキルとして `skills/` に置く）にまとめ、フックの知らせとリーダーの声かけの両方がそのスキルを使わせる。手順の中の機械的な部分はスクリプトが行う。

1. 状態を書き出す。issue のある作業ならその issue の `## 状態` コメント（グローバルの CLAUDE.md の決まりどおり、一つ前をたたむ）。issue が無ければ、まずリーダーに issue を立てることを提案し、立てるならそこへ書く。却下されたら `~/.cache/claude-handoff/` の下に引き継ぎのファイルを書く（`/tmp` は使わない）。この書き先はリーダーの決定。
2. 引き継ぎの中身。状態の在りか、作業フォルダ（cwd）、ワークツリーのパスとブランチ、関係する issue と PR、元のセッションの session_id、裏で走っている処理があればその扱い。
3. 新しいタブを立てる。同じワークスペースに、作業フォルダ（ワークツリーで作業していたらそのパス）を cwd にして、モデルとエフォートを選んで `claude` を起動し、引き継ぎの文面を渡す。`loop-handoff.sh` のタブ作成と起動の部分を共有するか、対話用の引数（cwd の明示、状態ファイルのパスの受け付け、`/loop` を付けない文面）を足すかは実装で決めてよい。
4. 掃除する（次節）。
5. 元のセッションの応答で、引き継いだ先（タブ）と掃除の結果を報告し、最後に「このセッションは閉じていい」と書いて止まる。次に誰かが引き継ぐとき、この元のセッションが掃除の候補になる。

### 掃除

一覧と閉じる操作はスクリプト、閉じてよいかの判断は元のセッションの Claude が受け持つ。言い回しの照合をスクリプトでしないのは、「閉じていいか確認させて」のような文と取り違えるため。

- 候補を出すスクリプト: `herdr pane list` から、元のセッションと同じワークスペースの Claude のペインを取り、次を外す。元のセッション自身、引き継ぎで立てたペイン、`agent_status` が `idle` でないもの、ループのセッション（`claude-loop-guard/<session_id>.prompts` の印があるもの）、transcript が読めないもの、最後のアシスタントの応答のあとにユーザーの入力があるもの。残った候補ごとに、タブ、セッション名、最後のアシスタントの応答の文面を出す。
- 判断: Claude が文面を読み、そのセッションが自分の仕事について「閉じていい」とはっきり書いているものだけを選ぶ。迷えば残す。
- 閉じるスクリプト: 選ばれたペインのタブを閉じる。閉じる直前に `agent_status` が `idle` のままかを確かめ直す。タブに Claude 以外のペインがあればタブを閉じずに残す。ワークスペースの最後のタブは閉じない。

## 実装者に任せること

- 予備の段の値、スクリプトとスキルの名前、`loop-handoff.sh` との共有のしかた。
- transcript の見つけ方（`agent_session.value` の session_id から `~/.claude/projects/*/<id>.jsonl` を探すなど）。
- テストは既存に倣い bats で書く（`chat-context-guard.bats`、`loop-handoff.bats`）。herdr を呼ぶ部分は `--dry-run` か偽の `herdr` で確かめる。偽物は本物と同じ JSON の形で答えることを確かめてから使う。
- README の「ループ以外の対話セッションの見張り」の節と、グローバルの CLAUDE.md の記述の更新。
