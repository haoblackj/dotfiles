# 背景の処理の進捗を帯に出す Mod の設計

2026-11-02

## 目的と経緯

Claude Code が背景の Bash で走らせる長い処理（モデルのダウンロード、ローカル LLM の一括処理）について、いま何％進んでいて、JST で何時ごろ終わるかを、入力欄の上に出す。

リーダーは cbr（comfy-batch-runner）の良い出来探索で、背景の Bash のダウンロードがいつ終わるかわからずに困った。
画面に見えるのは「シェルが動いている」という表示だけで、進み具合も終了時刻もわからない。

cbr の実例を調べてわかったこと。

- `hf download ... > dl-gemma.log 2>&1` のように出力をファイルへ回すと、`hf download` は進捗を一行も出さない（ログは `path=...` の一行だけ）。Claude は `du -sb` を 20 秒あけて二回測る手作業で速さを出していた。
- `download_*.sh` は curl でファイルを一つずつ落とすので、curl の進捗はファイル単位で、全体の何割かはわからない。
- `run_vlm.py`（llama.cpp の VLM に 13 種類の問いを 20 問ずつ投げる）は、ログには種類ごとの `face: 20 問 済み` しか出ないが、答えを一問ごとに `runs/<run名>/<種類>.jsonl` へ一行ずつ足している。

どれも「決まった場所で何かが増えていき、全体の量は起動する側が知っている」形をしている。
増えるものがファイルの大きさか行数かの違いしかない。
そこで Mod は進捗の行を読まず、登録された場所を測って全体の量と比べる。

## 目標

- 背景の処理が動いている間、入力欄の上に、処理一本につき一行で「名前、何％、バー、済んだ量／全体、速さ、残り時間 → JST の終了時刻」を出す。
- ダウンロード（バイト数）と、行を足していく処理（行数）の両方を同じ帯で出す。
- 終わったら帯から消し、完了の通知（トースト）を一度出す。
- 全マシンで使えるよう、dotfiles で配る。

## 目標でないもの

- コマンドの文字列（`hf download` など）からの自動検出。ダウンロードにしか効かず、LLM の処理を拾えないので採らない（リーダーと合意）。
- 背景の処理のログから進捗の行を読むこと。
- リーダーが手で打ったコマンドの進捗。登録するのは Claude が背景で始めた処理だけ。

## 失敗とみなすもの

- 帯がダウンロードのない時間も常に場所を取る。
- 処理が止まったり詰まったりしているのに、終わる見込みの時刻を出し続ける。
- 処理が途中で終わったのに、帯が残り続ける。

## 決まったこと

### 見た目（リーダーがモックで確かめた）

入力欄のすぐ上の帯（`AbovePrompt`）に出す。
ステータスラインはリーダーの自作の行（利用枠の残量など）で埋まっているので使わない。
横の固定パネルは幅が 144 桁以上ないと開かず、処理のない時間も場所を取るので使わない。

一行の形はモック（`/dl-mock`）で確かめたこの形。

```
⬇ gemma-4-12B Q8_0   62%  [██████    ]  7.8/12.6 GB  9.8 MB/s  残り 8分 → 16:24 JST
```

- 名前は cyan、割合と終了時刻は太字、量と速さは dim。
- 行数を数える処理では、量を `143/260 件`、速さを `0.8 件/s` のように出す。
- 残り時間は 1 時間以上なら `1時間12分`、未満なら `8分`（最小 1 分）。
- 処理が複数あれば一本一行で縦に並べる。何もなければ帯を出さない（`next(e)` を返す）。
- 完了したら帯から外し、`✔ <名前> 完了（12.6 GB、21分）` のトーストを出す（量と所要時間）。

モックの実装は `/home/yagu001/.claude/dev-mods/010f811c-3807-4173-a91e-815f377ed248/dl-progress-mock/` にある（使い捨て。見た目の参考にだけ使う）。

### 登録のしかた（リーダーと合意）

Claude が背景の処理を始めるとき、Mod が登録する道具（`$.tool.register`）を呼んで処理を登録する。
道具が受け取るのは次の四つ。

- 名前（帯に出す短い名前）
- 測る場所（ファイルかディレクトリのパス。複数可）
- 数えるもの（バイト数か行数か）
- 全体の量（バイト数か行数）

全体の量は、起動する側の Claude が知っている（Hugging Face の API でファイルの大きさを引く、問いの数を数える）。
`run_vlm.py` の思考あり／なしの二周のように、一つのコマンドで複数の段がある処理は、全体の量を合計で渡して一本の帯にする。

Claude が登録を忘れないよう、Mod は `prompt.compose` でシステムプロンプトに一節足す。
中身は「背景で数分以上かかる処理（ダウンロード、一括の推論）を始めたら、この道具で登録する」。

### 置き場所（リーダーと合意）

dotfiles の公開の自作スキルと同じ形にする。
実体をリポジトリ直下の `skills/<名前>/` に置き、`dot_claude/skills/symlink_<名前>.tmpl` で `~/.claude/skills/<名前>` へ symlink する。
Mod には cbr の中身も個人の情報も入れない（dotfiles は公開リポジトリ）。

## Claude の判断で決めたこと（リーダーに確かめた範囲外）

- 測る間隔は数秒（3〜5 秒）。速さは直近の一定時間（30 秒程度）の増え方から出し、一瞬の揺れで終了時刻が跳ねないようにする。
- 大きさや行数が 1 分ほど増えなかったら、終了時刻の代わりに `停滞中` と出す。今日の `run_vlm.py` のように呼び出しの失敗で詰まったとき、終わる見込みの時刻を出し続けないため。
- 登録した背景のタスクが、全体に届く前に終わった（失敗、中断、kill）ら、帯から外して `✖ <名前> 止まった（62%）` のトーストを出す。
- 全体の量に届いたら完了とみなす。背景のタスクの終わりを待たない（ダウンロード後に sha256 の照合などが続くことがあるため、量で判定する）。
- `hf download` は落としている途中のファイルを `<local-dir>/.cache/huggingface/download/` の下に `*.incomplete` として置き、終わると本来の場所へ移す。curl のスクリプトは `*.part` に落として改名する。どちらもディレクトリを丸ごと（隠しディレクトリを含めて）測れば途中の分も数えられる。登録の例として、システムプロンプトの節に「ダウンロード先のディレクトリを測る場所に渡す」と書く。
- セッションをまたいだ処理の引き継ぎはしない。登録はそのセッションの `$.state` に持つ。
- 登録は、背景の Bash を起動して結果が返った後に行い、その結果の `backgroundTaskId` を道具の引数（五つ目、任意）で渡す。背景のタスクと登録を結びつけ、途中で終わったことを判定するため。タスク ID を渡さなかった登録は、途中終了の判定をせず、停滞の表示だけで扱う。
- 済んだ量は、測る場所の今の大きさ（行数）をそのまま数える。登録時点の量を引かない。`hf download` や curl の `-C -` の再開では、既に落ちている分も進捗に入るのが正しいため。全体の量は、測る場所が最後に達する量（落とし終えたファイルの合計）を渡す。システムプロンプトの節には「測る場所には、この処理だけが書き込むディレクトリかファイルを渡す」と書く。
- 同じ名前で登録し直したら、その帯を上書きする（全体の量の訂正にも使う）。登録を取り消す手段も道具に持たせる（Claude が処理を止めたときに帯を外すため）。
- 行数で数える場所が複数なら、全ファイルの行数を合計する。行数は `$.fs.read` の上限（4 MiB）を超えうるので、`wc -l` を `$.process.run` で呼んでよい。
- 帯に並べるのは 5 本まで。それを超えたら最後の行を `ほか N 本` にする。
- 時刻はマシンのタイムゾーンに関係なく JST（UTC+9）で出す。
- 完了、止まった、のトーストは、ターンが動いていない待機中にも出す（待機中に知りたいため）。

## 作る側に任せること

- 道具の名前、引数の名前と形、システムプロンプトの節の文面。
- 背景のタスクが終わったことの検知のしかた。描画のフック（`UserMessage` の通知行）は、画面外の行で呼ばれない恐れがあるので、それだけに頼らない。Mod の API で、タスク ID からタスクの終わりを確実に拾える口を探して使う。見つからなければ途中終了の判定を落とし、停滞の表示で代える（その旨を報告する）。
- タイマー（`$.clock.every`）がターンの外でも動き続けるかの確認。動かないなら、帯の更新とトーストを待機中に出す別の手段を探す。
- `skills/<名前>/` に置いた Mod が `~/.claude/skills/` から本当に自動で読み込まれるかの確認。plugin-authoring の参照文書には「skills folder から自動で読み込まれる plugin」とあるが、条件（`SKILL.md` が要るか）までは書かれていない。読み込まれないときは、`linked/claude/settings.json` の `env` の `CLAUDE_CODE_PLUGIN_DIRS` で読み込ませる。
- クラウドのセッション（`install-cloud.sh`）での扱い。`install-cloud.sh` は `SKILL.md` を持つ `skills/*/` だけを写す。クラウドで動くかを確かめて報告する（memory: 変更のたびにクラウドでも動くかを確かめる）。
- テスト（`claude plugin test`）。少なくとも、割合と終了時刻の計算、停滞の判定、完了と中断で帯から外れること。
- README の「公開の自作スキル」の節への追記。
